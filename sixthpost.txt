☕ Gyaan Ki Baat #6 — System Design Essentials: Caching Patterns & Eviction ⚡

Caching is the secret behind sub-millisecond API latencies and handling millions of requests per second. 
But bad caching causes stale reads and database meltdowns! 💥👇

Here is a 2-minute breakdown every engineer should master:

---

1️⃣ Cache-Aside (Lazy Loading) 📦
App checks Cache → Miss? → Fetch from DB → Write to Cache → Return.
• Best for: Heavy read workloads.

2️⃣ Write-Through vs. Write-Back ✍️
• Write-Through: Synchronously updates Cache + DB together (High consistency).
• Write-Back (Write-Behind): Updates Cache immediately, asynchronously flushes to DB in background (Ultra-high write speed).

3️⃣ Eviction Policies 🗑️
• LRU (Least Recently Used): Evicts keys untouched for the longest time.
• LFU (Least Frequently Used): Evicts keys with lowest access count.

4️⃣ The Thundering Herd (Cache Stampede) 🐂
When a hot key expires (TTL=0), 10,000 concurrent requests miss cache and hit DB at once! 
• Fix: Use Redis Distributed Mutex Locks or Probabilistic Early Expiration (XFetch).
